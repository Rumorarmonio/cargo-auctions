# Cargo Auctions

SPA для просмотра грузовых аукционов, изучения их деталей и установки ставки.
Проект реализован как тестовое приложение на React и работает локально с mock API,
построенным по OpenAPI-контракту.

Требования и API-контракт описаны в [`SPEC.md`](./SPEC.md) и
[`openapi.auctions.v0.json`](./openapi.auctions.v0.json).

Описание использования AI находится в [`AI_USAGE.md`](./AI_USAGE.md). Правила
работы с проектом зафиксированы в кастомном [`AGENTS.md`](./AGENTS.md), включая
ссылки на инструкции по использованию SCSS-архитектуры:
[`src/shared/styles/README.md`](./src/shared/styles/README.md) и
[`src/shared/styles/core/README.md`](./src/shared/styles/core/README.md).

## Возможности

- список аукционов с пагинацией;
- фильтрация по параметрам, сохраняемая в URL;
- состояния загрузки, пустого результата и ошибки;
- детальная страница аукциона;
- маршрутная информация, данные о грузе, организаторе, оплате и торгах;
- история ставок с обработкой скрытого, пустого и ошибочного состояний;
- отдельная страница установки ставки;
- валидация цены ставки по `min`, `max` и `step` из API;
- уведомления об успешной и неуспешной установке ставки;
- prefetch деталей аукциона при наведении или фокусе на карточке;
- адаптивный интерфейс для desktop и mobile;
- мобильный Drawer для фильтров;

## Запуск

Требуется Node.js с поддержкой npm.

```bash
npm install
npm run dev
```

После запуска приложение доступно по адресу, который выводит Vite, обычно:
`http://localhost:5173`.

Главная страница `/` перенаправляет на `/auctions`.

## Основные маршруты

| Маршрут | Назначение |
| --- | --- |
| `/auctions` | Список аукционов и фильтры |
| `/auctions/:auctionUuid` | Детальная информация и история ставок |
| `/auctions/:auctionUuid/bet` | Форма установки ставки |

## Mock API

В режиме разработки API перехватывается MSW. Данные хранятся в in-memory store и
сбрасываются после перезагрузки страницы.

Реализованы mock-обработчики для endpoint’ов:

- `POST /auctions/list` — список аукционов;
- `GET /auctions/:auctionUuid` — детали аукциона;
- `GET /auctions/:auctionUuid/bets` — история ставок;
- `POST /auctions/:auctionUuid/bets` — установка ставки.

Фикстуры покрывают pagination, скрытую историю ставок, недоступную установку
ставки, победившие и отменённые ставки, пустые контакты, длинные маршруты,
несколько машин и `null`-значения.

Реальный backend, авторизация и сохранение данных между перезагрузками в проект
не входят.

## Архитектура и принятые решения

- React + TypeScript + Vite — базовый стек приложения.
- Feature-Sliced Design — организация кода по слоям `app`, `pages`, `widgets`,
  `features`, `entities` и `shared`.
- TanStack Router — маршрутизация и URL search params для фильтров.
- TanStack Query — загрузка, кэширование, prefetch и invalidation серверных данных.
- React Hook Form + Zod — организация и валидация форм через переиспользуемые
  общие поля, маски и схемы конкретных features.
- Mantine — базовые UI-компоненты, notifications и Drawer. Библиотека выбрана
  благодаря готовой стилизации и набору компонентов, что ускоряет сборку
  интерфейса по сравнению с более низкоуровневыми вариантами вроде Radix UI или
  shadcn/ui.
- SCSS Modules — стили компонентов и layout; общие стили находятся в
  `src/shared/styles`. Архитектура SCSS разделяет core-стили, utilities,
  variables, mixins и component-level modules по production-oriented подходу.
- Zustand — точечное состояние модальных окон. Модальная инфраструктура вынесена
  в отдельный typed registry/store/host, чтобы централизованно управлять
  вариантами окон, параметрами и анимациями.
- MSW — локальная реализация API для разработки и интеграционных тестов.
- Orval — генерация типов, API-клиента и TanStack Query hooks по OpenAPI-схеме.

SCSS-архитектура, modal infrastructure и организация валидации форм выполнены
в стиле production-проектов: общие механизмы отделены от конкретных экранов и
фич, а повторно используемые решения вынесены в shared-слой.

Для контроля качества используются кастомные конфигурации ESLint, Stylelint и
Prettier, перенесённые и адаптированные из используемых production-проектов.

Для списка аукционов используется ручная обёртка над сгенерированным API hook:
это позволяет представить `POST /auctions/list` как query с ключом,
зависящим от параметров фильтрации и пагинации.

## Проверки

```bash
npm test                 # unit- и интеграционные тесты
npm run typecheck        # проверка TypeScript
npm run build            # production-сборка
npm run lint             # ESLint
npm run stylelint        # Stylelint для CSS/SCSS
npm run format:check     # проверка форматирования Prettier
```

Генерация API-кода из OpenAPI выполняется командой:

```bash
npm run generate:api
```

Для ручной проверки в Chrome рекомендуется проверить:

1. загрузку списка, фильтры и переход по страницам;
2. открытие деталей аукциона и историю ставок;
3. скрытые, пустые и ошибочные состояния истории ставок;
4. форму ставки, ошибки валидации и успешную отправку;
5. обновление связанных данных после установки ставки;
6. desktop- и mobile-отображение, включая Drawer фильтров и модальные окна.
